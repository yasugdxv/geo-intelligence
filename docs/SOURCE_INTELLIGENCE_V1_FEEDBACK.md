# SOURCE_INTELLIGENCE_V1 フィードバック記録

**使い方**: SOURCE_INTELLIGENCE_V1（`docs/SOURCE_INTELLIGENCE_V1_FREEZE.md`）の評価期間中に見つかった問題・改善案を
**ここへ記録する**。評価期間中は V1 の機能（Backend / Frontend / SQL）を**直接変更しない**。
修正が必要になった場合は `SOURCE_INTELLIGENCE_V1_1` 等の次版として扱う。

## 記録ルール
- 1件ごとに ID（FB-001, FB-002 ...）を振る。
- 「再現手順」「期待した動作」「実際の動作」「影響範囲」「分類」を書く。
- 分類: `Bug`（仕様と異なる）/ `Gap`（V1で意図的に未対応）/ `Quality`（精度・使い勝手）/ `Idea`（改善案）。
- DB状態（Source件数など）に依存する場合は、確認時点の日時を書く。
- 既知の課題は Freeze Manifest の「Known Issues / Future Work」に記載済み（重複して書かない）。

## 記録テンプレート

```
### FB-000: （短い題名）
- 日時 / 記入者:
- 画面 / API:
- 再現手順:
- 期待した動作:
- 実際の動作:
- 影響（誰が・どの程度困るか）:
- 分類: Bug / Gap / Quality / Idea
- 次版への提案:
```

## 記録

### FB-001: テーマ探索の「検索」が何をする画面か分かりにくい
- 日時 / 記入者: 2026-10-05 / ユーザー（スクリーンショット付きの指摘）
- 画面 / API: `/geo/theme-discovery`（`theme-explorer-panel.tsx`）、`GET /api/geo/theme-explorer?q=`
- 再現手順: テーマ探索を開く。1行の小さな「検索」ボックスと「検索」ボタンだけが見える。
- 期待した動作: 調査したいことを**自然言語の調査プロンプト**として書く画面にしたい。ボタンは「検索」ではなく「テーマ探索開始」。
  プリセットを選ぶと文章が入力欄に入り、それを少し書き換えるだけで使える。
- 実際の動作: 1行入力＋「検索」ボタン。長い文章を書く前提になっておらず、何を入力すべきか分からない。
- 影響: 初見のユーザーが使い方を理解しにくい（評価の入口で躓く）。
- 分類: Quality（使い勝手）
- 対応: **V1_1として実装済み**（2026-10-05）。V1 snapshot（`freeze/SOURCE_INTELLIGENCE_V1/`）は変更していない。
  変更内容と差分ファイルは `docs/SOURCE_INTELLIGENCE_V1_1_CHANGELOG.md` を参照。

### FB-002: 「テーマ探索開始」を押しても何も起きない／プリセット不要／フィルターの意味が分からない
- 日時 / 記入者: 2026-10-05 / ユーザー
- 画面 / API: `/geo/theme-discovery`、`GET /api/geo/theme-explorer`
- 再現手順: 文章を入れて「テーマ探索開始」を押す。
- 期待した動作: 押したら探索が始まったと分かり、結果（または結果が無い理由）が見える。
- 実際の動作: 文章の解釈に数秒かかるのに進行表示が無く、さらに本番のテーマ候補が0件のため結果が空のまま変化が見えなかった。
  フィルター（地域・テーマカテゴリ・注目度・期間・新規のみ）は何を絞るのか分かりにくい。プリセットは不要。
- 影響: 操作しても反応が無いように見える。フィルターの意味が分からず使われない。
- 分類: Quality（使い勝手）＋ Bug（AIが抽出した地域を厳密一致で適用し、取りこぼしていた）
- 補足（根本原因）: **本番のテーマ候補は0件**。候補は「承認済みのSituation Link」から生成される設計で、現在は承認済みが0件のため生成されていない
  （`geo_episode_cluster_links` 2件、承認済みの状況データ0件）。画面の改善だけでは候補は増えない。
- 対応: V1_1として実装済み（`docs/SOURCE_INTELLIGENCE_V1_1_CHANGELOG.md` 変更2）。
- 次版への提案: 「テーマ探索開始」で、直近の記事から候補テーマをその場で提案する機能（候補生成のオンデマンド化）。要判断。

### FB-003: 「テーマ探索開始」は、記事からテーマ候補をその場で提案してほしい
- 日時 / 記入者: 2026-10-05 / ユーザー
- 画面 / API: `/geo/theme-discovery`
- 再現手順: 候補が0件の状態で「テーマ探索開始」を押す。
- 期待した動作: 直近の記事から、継続して見る価値のあるテーマ候補が提案される。
- 実際の動作: 承認済みSituation Linkから作られた候補しか出ず、0件のままで何も起きない。
- 影響: 評価の入口で価値が見えない。
- 分類: Feature（FB-002の次版提案）
- 対応: **V1_1として実装済み**（2026-10-05、`docs/SOURCE_INTELLIGENCE_V1_1_CHANGELOG.md` 変更3）。
