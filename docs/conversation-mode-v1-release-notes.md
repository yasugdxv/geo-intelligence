## 3. 既知の限界（リリース前の既知事項）

### 3.1 権限変更後も、既に表示された文面は画面に残る
Evidence Gate は、権限が変わった後の**次のサーバー呼び出し**から、取り消された根拠を使わず・表示しない。ただし次の限界がある。

1. **すでに画面に表示された文面は、サーバーを呼ぶまで消えない。** 権限が変わった瞬間に画面を書き換える仕組みはない。
2. **根拠の出典IDを引かずに言い換えた発言は、伏せ字にならない**（どの根拠から作られたか分離できないため）。代わりに、権限変更より前のAI発言は今後の回答の材料に使わず、会話の整理（事実・推測・問い）は全消去する。ただし、画面の履歴にはその発言が残る。
3. **ブラウザ内（localStorage）の保存コピーは、会話を開き直して `refresh` が成功するまで、権限変更前の内容のまま残る。** 会話は、会話モードの画面から1件ずつ削除できる（§7）。
4. 画面のコピー、スクリーンショット、他の場所へ貼り付けた内容は対象外。
5. 根拠のスナップショットは、権限の再確認で題名・日付を取り直すが、要点・主張の本文は保存時点のもの。

### 3.2 AI呼び出しの「1会話40回」上限は、目安である
画面（呼び出し数の横の注意書き）と `/config` の `limits.note` にも明記している。**ログイン中で、会話テーブルが作成済みのときは、サーバーに保存した回数も使う（§8、実装済み・実DBでは未確認）。未ログイン・保存なしでは、プロセス内の概算のまま。** 次の表は、保存済みの回数を使わない場合（匿名・テーブル未作成）の挙動。次の方法で回避できることを、フェイクLLMで確認した（実LLM・費用なし）。

| 方法 | 結果 |
|---|---|
| サーバーを再起動し、クライアントが回数を0に巻き戻す | 続行できる |
| 別プロセス（複数ワーカー）で同じ会話IDを使う | プロセスごとに40回通る |
| 新しい会話を何度も開始する | 会話をまたいだ累計上限なし（匿名でも可） |

実LLM E2Eスクリプトの「全体60回」は、スクリプト内のカウンタで、別の仕組み。

### 3.3 その他
- 状態をクライアントが保持する方式のため、改ざんされた要点・主張の本文を、自分の会話の材料に入れることはできる（他人の資料へのアクセスにはならない。出典は毎回サーバーが権限で検証する）。
- 文言は日本語のみ。
- 実LLMでの会話品質・遅延・費用は未確認。
- 匿名でも利用できる（保存はブラウザ内のみ）。ログイン用の認証情報は、既存の仕組みで低権限の識別子が自動発行され得るため、ログイン必須にしても強い制限にはならない可能性がある。

## 7. 会話の削除（2026-10-19実装）

会話モードの画面で、会話を1件ずつ削除できる（履歴の各行のごみ箱ボタン、会話中は「この会話を削除」）。削除前に確認ダイアログを出し、選んだ1件だけを削除する。ほかの会話、他モードの会話、通常チャットの履歴、無関係のlocalStorageのキーには触れない。

### 削除対象と保存先
| 保存先 | 削除されるもの | 削除できる条件 | 削除後も残り得るもの |
|---|---|---|---|
| ブラウザ内（localStorage `verdant_geo_conversation_mode_v1`） | 選んだ会話IDの1件だけ。残りの会話はそのまま。最後の1件を消してもキーは空の配列として残る | 保存内容が読めるとき。**読めない・形式が違うときは何も書き換えず、「削除できませんでした」と表示する** | 別のブラウザ・別のPCに保存された同じ会話のコピー、画面のコピー・スクリーンショット |
| サーバー（`geo_intelligence_ai_conversations` の1行） | 自分（認証済みID）が所有する、その会話IDの1行 | ログイン中（認証情報あり）で、保存先のテーブルが作成済みであること。**現状、実DBにテーブルが無いため、サーバー削除は実DBでは未確認** | DBのバックアップ（保持期間が過ぎるまで）。DB管理者が事前にエクスポートしたデータ |
| 通常チャットの履歴（`verdant_geo_chat_conversations` ほか） | **対象外（削除しない）** | — | — |

### 結果の表示（ブラウザ内とサーバーを分けて表示し、失敗を成功と表示しない）
| サーバーの応答 | 表示 |
|---|---|
| 削除できた | 「削除しました」 |
| 404（該当なし。会話が無い・他人のもの。サーバーは区別しない） | 「該当する会話は見つかりませんでした（保存されていないか、すでに削除済み）」 |
| 503（保存先が未作成など、サーバー保存が使えない） | 「サーバー保存が利用できないため、サーバー側の削除は確認できませんでした（削除できたとは言えません）」 |
| 未ログイン・認証が無効（401を含む） | 「サーバー側は削除していません」。未ログイン時はサーバーへ何も送らない |
| その他の失敗・通信エラー | 「削除に失敗しました。サーバー上の会話は残っている可能性があります」（警告表示）。ブラウザ内の結果とは別に表示する。サーバーに残っている会話は、一覧に戻るので、もう一度削除できる |

### 本人確認
サーバー削除は既存の `verify_ios_identity`（`X-IOS-Credential` ヘッダー）で認証したIDを所有者として、`owner_id` が一致する行だけを削除する。クエリやヘッダーで所有者を名乗っても無視される。他人の会話ID・存在しない会話IDは、同じ404の応答で、会話の有無を推測できない。管理者でも他人の会話は削除できない。Feature Flag がOFFでも、削除はできる（データの削除を妨げない）。

### 動作
- 削除中は、生成・停止・再開・別の削除をできなくする（連続クリックでも、サーバーへの削除リクエストは1回）。
- 会話中の画面から削除すると、テーマ選択に戻る。モード切替の引き継ぎに、削除した会話の内容は残らない。
- 削除後、一覧は、ブラウザ内とサーバーの保存分から読み直す。

## 11. エラーと遅さの原因の修正、LINE風の見た目、役の強化、半自動の進行（2026-10-19）

利用者から「回答が遅いし、エラーになる」「LINEのようなビジュアルが欲しい」「役の設定が弱く、崩して役に寄せてほしい」「次へ進むのは半自動でもよい」と指摘を受けて対応した。

### 1. エラーと遅さの原因（同じ1か所だった）と修正
- **原因**: 会話の開始時に呼んでいた、既存の「分析」（社内資料をAIが要約する呼び出し）。①約15〜16秒かかり（発言1回は約4秒）、②ときどき、AIが指定の形式で返さず、そのまま失敗していた（`GeoLLMError` → 開始が丸ごと502）。ログ上は、ストリーミングが「HTTP 200の中のエラーイベント」で返すため、見えにくかった。実LLMで、コンサルの開始を3回実行して再現した（1回目: 失敗、2・3回目: 成功）。
- **修正**: 分析のAI呼び出しをやめ、**社内資料の検索結果（題名・日付・抜粋）を、そのまま根拠にする**（DB読み取りのみ。権限は従来どおり適用）。発言するAIが、題名と抜粋を直接読む。出典 [S1] などは、これまでどおり。
- あわせて、AI呼び出しが一時的に失敗したときは、少し待って**自動で1回やり直す**。
- 開始の所要時間（実LLM、ログイン済み条件）: ギャル 24秒 → **11.8秒**、コンサル 失敗/45秒 → **8.6秒**、会議 36秒 → **18.5秒**。実LLMで3モード × 4操作（開始・質問・続き・チップ）の12回は、すべて成功した。

### 2. LINE風の見た目（画面）
- 話者ごとの**丸いアイコン**（ギャル💅・おっさん🍶・コンサル💼・相棒🔍・まとめ📝、会議の主体は🏛️🛡️🏭🌐）、AIは**白い吹き出し**（左）、自分は**緑の吹き出し**（右）、時刻、自分の発言のあとにAIが答えたら**「既読」**、青い背景のトーク画面。
- 生成中は、点が跳ねる**「入力中…」の吹き出し**（「〇〇が入力中…」）。
- 注意書きは、小さな**「ⓘ 注意」**にまとめた（カーソルを載せると全文）。根拠あり・推測・質問のバッジと、出典リンクはこれまでどおり。

### 3. 役の強化
- **ギャル**: 崩したタメ口（「ってかさ」「ガチで」「ワンチャン」「〜じゃん」）、絵文字1〜2個、敬語なし、短い質問・ツッコミ中心。

- **相棒**: タメ口寄り（「ちょい待って」「それ、根拠どこ？」「逆もありえない？」）、妥当なら認める。
- **会議の主体**: その主体らしい話し方（外交当局は慎重で婉曲、軍・治安機関は簡潔で断定的、企業はコストと契約の言葉、など）。

## 14. 深い根拠: Web調査とExpert AIの基盤知識（2026-10-20）

### 追加した根拠（出典番号）
| 番号 | 中身 | 取得元 |
|---|---|---|
