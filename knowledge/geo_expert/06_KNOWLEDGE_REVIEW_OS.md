# Review OS

## 最初に行うRoot Premise Check

細部を直す前に、分析のスタートラインが正しいか確認する。

1. この局面を動かすKey Stakeholderは誰か。設定自体が正しいか。
2. Key Stakeholderの目的を今回の発言・政策から直接置いていないか。
3. Persistent Preferenceの根拠は、複数の過去行動にあるか。
4. Ultimate Objective、Strategic / Relationship Preference、Issue Objective、Observed Actionが混同されていないか。
5. Observed Actionが上位志向と逆なら、そのGapを説明するDriving Forceを検討したか。

このスタートラインが誤ると、その後のステークホルダー分析・主シナリオ全体が歪むため、Criticalとして扱う。

## Mode A：テーマ設計・壁打ち

目的：ニュースや問題意識を、レポート化できる中心仮説と論点へ変換する。

確認項目：

1. このテーマを扱う価値
2. 最初の違和感
3. Key Stakeholder / 意思決定構造
4. Key Stakeholderの上位目的・Persistent Preference
5. 今回のObserved ActionとのGap
6. Audience・Driving Force
7. 周辺ステークホルダーと背景の力学
8. 暫定的な一言見立て
9. 主シナリオと代替シナリオ
10. 検証・反証すべき情報
11. 自社への影響経路
12. レポート構成
13. 担当者への学び

## Mode B：調査設計

目的：中心仮説を検証・反証するための調査計画を作る。

確認項目：

1. 調査目的
2. Key Stakeholderと意思決定権
3. Persistent Preferenceを支持・反証する過去事例
4. Preference-Action Gapの競合説明
5. Audience仮説
6. ステークホルダーマップ
7. 確認済み事実
8. 不足情報
9. 優先調査項目
10. 情報源候補・Source of Sources
11. 専門家への質問
12. 反証条件
13. モニタリング指標

## Mode C：構成案レビュー

目的：構成が表面的、網羅的、一般論的になっていないかを確認する。

チェック：

- 冒頭に中心見立てがあるか
- Key Stakeholderがいるのに全主体を横並びから始めていないか
- Key Stakeholderの上位目的が示されているか
- 今回の行動と上位志向のGapが説明されているか
- Audience・支持基盤・政治的Driving Forceが必要な範囲で入っているか
- 見出しがニュースの時系列説明だけになっていないか
- 主要主体と内部勢力が不足していないか
- 相手側の鏡像分析があるか
- 背景の力学が示されているか
- 調査項目が中心仮説とつながっているか
- 自社影響が広すぎる、弱すぎる、飛躍していないか
- 役員に何を考えてもらうかが明確か

## Mode D：ドラフトレビュー

目的：専門家レビュー前の一次フィルターとして本文を確認する。

### Root premise

- Key Stakeholderの設定が妥当か
- 人物の目的を単発発言から決めていないか
- Persistent PreferenceとCounter Evidenceがあるか
- 上位目的とIssue Objectiveを分けているか
- Preference-Action Gapを検討しているか

### 見立て

- ニュース要約で終わっていないか
- 最初の違和感が明確か
- 主シナリオがあるか
- 主シナリオを置く理由が示されているか
- 可能性列挙に逃げていないか
- 代替仮説が主シナリオと同じ重さで並びすぎていないか

### Stakeholder / Driving Force

- 国を一枚岩としていないか
- 全主体を同じ深さで扱っていないか
- 必要な内部勢力が分解されているか
- 「共和党」「民主党」「保守」「強硬派」「超党派」等のラベルの中身を確認しているか
- 選挙区、支持基盤、献金、産業・雇用、党内関係が必要な場合に見えているか
- 相手側にも鏡像分析があるか
- 誰が得て、誰が損をするか示されているか

### Audience / Signal

- 誰に何を見せているかを検討したか
- Audienceを根拠なく作っていないか
- 強い言葉と実質的な政策内容を分けているか
- SignalとSubstanceの差があるか

### 証拠

- 事実、公式主張、観測、推論、仮説が区別されているか
- 因果関係を断定しすぎていないか
- Persistent Preferenceを確定人格として書いていないか
- 反証条件があるか
- 撤回、修正、実施状況を確認しているか
- 語られていない論点を見ているか

### Media / Source

- メディアのSelection、Placement、Prominence、Framing、Omissionを確認できる場合に見ているか
- デジタル記事だけから紙面・放送上の重要度を推測していないか
- 主流と異なる情報を「正しい」と扱っていないか
- Source of Sourcesを優先調査候補として使えているか

### 政治・経済

- 選挙、議会、予算、連立を見ているか
- 産業、地域、支持基盤との接続があるか
- 制度上可能かを確認しているか

### 企業接続

- 外部事象から自社影響までの経路があるか
- 直接影響と間接影響が分かれているか
- 無理に重大リスク化していないか
- 意思決定、準備、監視へ接続しているか

### 表現

- 断定の強さが証拠の強さに合うか
- 根拠ある主張を弱めすぎていないか
- 「可能性がある」の連続で主張がぼやけていないか
- 背景説明が中心判断を埋めていないか
- 役員に考えてもらうことが明確か

## Mode E：担当者育成

結論だけでなく、次を説明する。

1. 最初に何を見るべきだったか
2. Key Stakeholderは誰だったか／なぜ一人に集約できなかったか
3. どの読み方が表面的か
4. 上位目的と局面行動をどう分けるか
5. どのAudience・Driving Forceを見落としていたか
6. どの主体を見落としていたか
7. どの基礎知識が必要か
8. 仮説をどう作るか
9. 何を反証条件にするか
10. 他テーマへ何を応用できるか

## レビュー結果の優先順位

- Critical：事実誤認、Key Stakeholderや上位目的の誤設定、重大な因果断定、意思決定を誤らせる問題
- Major：Persistent Preference、Preference-Action Gap、Audience、中心仮説、力学、反証、自社接続に関する大きな不足
- Minor：表現、順序、補足情報の改善

修正点を多数列挙する場合も、最優先3点を先に示す。

## 断定表現のレビュー方針

レビューでは、断定表現を機械的に弱めない。弱めるべきなのは根拠のない断定であり、根拠に基づく主シナリオは維持し、根拠・留保・反証条件で支える。

### 弱めるべき場合

- 根拠が不足している
- 事実と仮説が混在している
- 確認できていない意図、Persistent Preference、Audienceを事実として書いている
- 反証条件がない
- 読み手に確定事実と誤認させる

### 維持・強化すべき場合

- 根拠に基づく専門的見立てである
- レポートの中心仮説として必要である
- 表現を弱めると論点がぼやける
- 代替仮説や反証条件を補えば成立する

### 推奨する添削姿勢

悪い修正：
「断定的なので、可能性があるに弱める」

良い修正：
「主シナリオとしては成立するため、見立ては維持する。根拠、留保、見立て変更条件を補う」
