## 1. 位置づけと構成

### 1.1 位置づけ
| | エキスパートAI相談 | **インテリジェンスAI(会話)** |
|---|---|---|
| 一言 | 局面の読みを、Expert AIのフルケイパビリティで**読みに行く** | Expert AIの**考え方**を使い、ソース横断で**壁打ち**する相手 |
| 目的 | 読み筋（主軸・対抗・反対仮説）を出す | 質問・調査・相談で、理解と論点を深める |
| Expert AIの使い方 | 推論エンジン全体 | 専門家の型・承認済み知識・説明モデル・アクターの知見 |
| 進め方 | 入力 → 長時間の生成（数分） | 対話・即応（初回回答 目標10秒、§7） |
| 成果物 | 読みのポートフォリオ | 回答・論点・次に調べること |

### 1.2 画面構成（ユーザー指示の反映）
- **モード**を切り替える。
  - **通常モード**: フラットな会話。プリセット（分析テンプレート）を用意。**ソース横断が基本**。
  - **その他モード**（現状の3モード）: モードごとの機能でチャット（ギャルとおっさんとわたし／コンサルとわたしと同僚／ロールプレイング会議）。**今の機能を維持**。
- 呼び方は「インテリジェンスAI(会話)」に統一（旧称「地政学専門家AI」はエキスパートAI相談と紛らわしいため廃止。2026-10-22に見出しは変更済み）。

## 2. 設計原則

1. **ソース横断が既定**: 1つの質問を、使えるすべてのソースへ同時に投げる。ソースの選択を質問の前に強いない（あとから絞れる）。
2. **根拠をレーンで分ける**: 社内（検証済み）／Expert AI知識／記事／Web（未検証）／面談ログ（人の見解）。混ぜて断定しない。
3. **専門家の型でガイドする**: 回答を「事実／見立て／反対の見方／次に見ること」に分け、見落としている切り口を示す。
4. **権限は毎回、ソースごとに、fail-closed**: 取れないソースだけ空にして、他は使う。
5. **外部送信は最小・同意つき**: Webへ送るのは問いの題名レベルだけ。社内資料・会話内容は送らない。
6. **断定しない・捏造しない**: 出典の無い事実は言わない。未知の出典番号を引いた主張は降格する。
7. **更新が止まっていることを隠さない**: 鮮度が古いソースは、そう表示する（「0件＝変化なし」と言わない）。

### 3.1 現状のギャップ
1. プリセット無しの**自由質問**は、旧簡易チャット経由で、記事・Web・面談ログを使わない。
2. プリセットごとに対象ソースが固定（例: `past_cases` は reports・knowledge のみ）。**横断が既定になっていない**。
3. 専門家の型は、回答の構造・ガイドに**前面に出ていない**。
4. 遅いソース（Web）を待ってから全体が返る（会話モードのような後追い取り込みが無い）。
5. 会話 → エキスパートAI相談への**引き継ぎ**が無い。

## 4. 新規に作るもの

### 4.1 「横断で答える」ランナー（`run_cross_source`）
プリセットを選ばない自由質問の入口。`run_preset` の部品を再利用する。

1. **意図の解釈**（LLM 1回）: 質問 → ①質問の種類（事実確認／調査／比較／見立て相談）、②検索語（日英・最大6）、③関係しそうな切り口（§4.3）、④Webが必要そうか。`plan_terms` と統合する。LLM不可なら、語の分割で代替（既存と同じ）。
2. **並列収集**: 既定は**使えるソース全部**（reports, knowledge, articles, monitoring, source_library, external_network）。Webは同意があるときだけ。ソースごとに待ち時間の上限（§7）。
3. **統合**: `_merge_evidence` で重複排除・ref番号付与。レーンと信頼度を付ける（§4.2）。
4. **回答**（LLM 1回）: 専門家の型で構造化（事実／見立て／反対の見方／次に見ること）。`_validate_items` で、未知のrefを破棄。
5. **状態の表示**: `_status_rows` を、ソースごとの件数・失敗・権限なし・同意なしとして画面に出す。
6. **`context` を返す**: 既存の `followup` で追加質問できる。

プリセットは、「このランナーに渡す**分析テンプレート**（指示＋出力の見出し＋既定のソース）」として位置づけ直す（挙動は互換）。

### 4.2 根拠のレーンと信頼度
| レーン | ソース | 事実として使えるか | 表示 |
|---|---|---|---|
| internal | reports（承認済み） | 使える | 社内（検証済み） |
| expert_knowledge | knowledge（承認済み） | 使える | Expert AI知識 |
| article | articles / events / monitoring | 報道として引用（未検証） | 記事 |
| network | external_network（面談ログ） | **個人の見解**として引用 | 面談ログ（見解） |
| web | web（同意が必要） | **使えない**（参考） | Web（未検証） |

- 回答の「事実」欄に入れてよいのは internal / expert_knowledge の根拠だけ。他は「報道では〜」「〜という見解」「Webでは〜（未検証）」と書く。
- 根拠のチップに、レーンの種類を表示する（会話モードの S/K/F/W と同じ考え方）。

### 4.3 専門家の型でガイド
- **回答の構造**: 事実／見立て（「見立て」と明示）／反対の見方／次に見ること（先行指標・読みを変える条件）。
- **切り口チップ**: 6つの切り口（アクターの意図と能力／制度上の制約／過去の類似事例／先行指標／反対の見方／日本企業への影響）のうち、今回の根拠でカバーできたものと、**資料が無い切り口（盲点）**を示す。押すと、その切り口で追加質問する。
- **知識の裏付け**: `gather_expert_context` の結果を、解釈と回答のプロンプトに渡す（知識が無ければ「裏付けなし」と明示し、無い知識を作らない）。
- LLMの追加呼び出しは0〜1回（回答のスキーマに、切り口の充足を含めて1回で済ませる案を第一候補）。

### 4.4 モード切替UI
- 通常モード: 会話＋プリセット（テンプレート）。ソースの状態バーと、ソースの絞り込み（既定は全部）。
- その他3モード: 既存のまま。**根拠取得を、将来は同じアダプタ群へ統一**（現状は会話モード側に独自の検索があり、重複している）。

### 4.5 エキスパートAI相談への引き継ぎ
- 会話の論点・前提・使った根拠を、既存の `geo_ios_analysis_session_service.create_session`（＋intake）に渡して、読みの本格実行へ誘導する。
- 会話側では「見立て」までを出し、**本格的な読みはエキスパートAI相談**、と役割を分ける。

## 5. API設計（案）

`POST /api/geo/intelligence-ai/ask`（ストリーミング、NDJSON。既存の会話モードと同じ方式）
- 入力: `message`、`history`（クライアントが保持。サーバーは会話を持たない）、`sources`（省略=全部）、`with_web`（同意）、`template`（プリセットid、省略可）、`context`（追加質問時）
- イベント: `status`（段階の表示）／`source_status`（ソースごとの結果）／`evidence`（根拠の追加。遅いソースは後から）／`answer`（回答）／`guide`（切り口チップ）／`done`／`error`
- 既存の `/presets/run`・`/presets/followup`・`/chat` は**互換のまま維持**。

状態: ステートレス（既存と同じ）。保存は、既存の会話ストア（`geo_intelligence_ai_conversation_store`）を再利用。SQLの追加は不要。

## 6. 権限・セキュリティ

- アダプタごとに `requester_context` で判定。**毎ターン、ゼロから再評価**（前ターンの結果を信用しない）。取り消された根拠は、回答から撤回する（会話モードの `authorize_evidence` の方式）。
- Web: 同意が無ければ呼ばない。送るのは「問いの主題」だけ（社内資料・面談ログ・会話履歴は送らない）。送った検索語を画面に出す。
- evidence内の指示文には従わない（データとして扱う）。
- 面談ログは「個人の見解」としてのみ引用し、本人が確認した専門性として扱わない。
- 回数・コストの上限（1会話あたりのLLM呼び出し上限）を設ける。会話モードと同じ考え方。

## 7. 性能・コスト目標（案）

| 項目 | 目標 |
|---|---|
| 初回回答（Webを除く） | 10秒以内（p50） |
| ソース別の待ち上限 | 内部DB 3秒／記事 4秒／Web 8秒（超えたら後追い） |
| LLM呼び出し | 解釈1＋回答1（＋切り口ガイド 0〜1）／問い |
| Web | 後追いで取り込み。取れなければ、取れなかったと明示 |

現状の参考値: プリセットは語の計画と収集、分析で数十秒かかることがある（`timings` に記録あり）。会話モードの実測は、初回発言5〜13秒。

## 9. テスト計画

- **単体**: ダミーのアダプタで、並列収集・部分失敗・タイムアウト・重複排除・未知refの破棄・レーン分け。

## 12. 実装状況（2026-10-22 更新）

### P0 完了: 表示・文言の整理
通常モードのカード説明、モード選択下の説明、初期メッセージ、見出し（「インテリジェンスAI(会話)」）。

### P1 完了: ソース横断の自由質問（`/ask` 非ストリーミング版）
- **実装方針（設計からの変更点）**: `run_cross_source` を新設せず、**非表示のプリセット `cross_source`（`HIDDEN_PRESETS`）として、既存の `run_preset` / `followup` をそのまま使う**。既存6プリセットの定義・テストは変更なし。
- **エンドポイント**: `POST /api/geo/intelligence-ai/presets/ask`（設計の `/ask` から、既存のプリセットのルーターへ配置。`api_server.py` の変更は不要）。機能フラグ `GEO_IA_CROSS_SOURCE_ENABLED`（既定OFF）。`GET /presets` の応答に `cross_source_enabled` を追加。
- **既定のソース**: reports / knowledge / articles / monitoring / events / source_library。外部ネットワークはログイン時のみ。Webは画面の同意チェックがあるときだけ。
- **根拠のレーン**: 出典に `lane` を付与（internal / expert_knowledge / article / network / source_library / web）。**事実の欄に入れてよいのは internal / expert_knowledge だけ**。それ以外の根拠だけの主張は、サーバー側で「見立て」へ降格する（`demoted`。情報ソースの登録情報だけの主張は、その旨を注記）。
- **回答の構造**: 確認できる事実／見立て／反対の見方／次に見ること。専門家の6つの切り口を、指示文に含めた（切り口チップ・盲点の提示はP2）。
- **画面**: 通常モードの自由入力を `/ask` へ接続（フラグONのとき）。結果はプリセットの結果カードで表示し、出典にレーンのバッジ、根拠の内訳の行を追加。続けて入力すると、既存の追加対話（`/presets/followup`）になる。Web同意のチェックは、フラグON かつ Web検索キーがあるときだけ表示。フラグOFFでは従来どおり。
- **検索語の修正**: `plan_terms` が、`Strait_of_Hormuz` や `UnitedStates` のように単語をつなげて返す問題を、空白区切りに直す（全プリセットに効く）。
- **テスト**: 新規 `tests/test_geo_intelligence_ai_cross_source.py`（13件）、画面テスト 11項目。既存の関連テスト・画面テスト（89項目）は全通過。
